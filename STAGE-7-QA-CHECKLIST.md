# Stage 7 — Demo Conversion & Commercial QA Checklist

## Demo conversion layer
- [ ] Explains what the system does.
- [ ] Explains how it helps the prospect business.
- [ ] Explains what happens after the prospect says yes.
- [ ] EN/ES content is correct where enabled.
- [ ] One final CTA only.
- [ ] Local Lead Forge + localleadforge.com branding visible.
- [ ] No internal infrastructure jargon exposed.
- [ ] No guaranteed lead/sales/revenue/ROI claims.
- [ ] Existing noindex/unofficial-demo/safety controls preserved.
- [ ] Mobile and desktop render correctly.

## Direct mail compatibility
- [ ] QR/fallback URL points to correct prospect demo.
- [ ] Physical copy uses compliant benefit language.
- [ ] Prospect address/recipient source is recorded before any print/send authorization.
- [ ] No print/postage/mail side effect without explicit owner authorization.

## CRM
- [ ] Email state distinguishes SENT / SENT-NO-BOUNCE / BOUNCED / REPLIED.
- [ ] Physical-mail state is separate from email state.
- [ ] Contact source and verification date recorded.
- [ ] Demo visit is never inferred without evidence.
- [ ] Meeting and won/lost states are independently tracked.

## Reply-to-close
- [ ] Standard price and package language are consistent.
- [ ] Common objections have safe responses.
- [ ] No promises beyond verified scope.
- [ ] Payment and activation gates remain enforced.

## Release rule
Stage 7 may be merged as documentation/process groundwork before live sending. No commercial email or physical-mail release is authorized by merging this checklist or its companion documents.
